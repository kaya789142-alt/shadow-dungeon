# V2.2 問題分析與驗收

## 起始狀態與重現

遠端 `main` 的 V2.1 合併提交是 `263333c`。本地直接從該提交建置，作為同場景比較及舊快取測試的基準。雲端網路代理在連線至 GitHub Pages 網域時回覆 HTTP 403，故本次無法直接確認正式網址當時送出的 HTML 或快取版本。

- V2.1 Service Worker 對每次導覽都優先回傳已快取的首頁。新版 Worker 也會在舊頁關閉前等待，因而可重現頁面持續顯示舊建置。Chromium 測試也曾觀察到舊版安裝後的第一次重新載入仍取到舊首頁，下一次導覽才取得 V2.2。V2.2 安裝時確定首頁和預快取資源完整，啟用時移除舊 Worker 快取中的首頁項目，並保留它的雜湊資源。頁面收到新的建置識別碼後會儲存和重新載入。
- V2.1 個別角色紋理載入失敗時會用簡化向量角色繼續遊玩。V2.2 檢查必需紋理、動作圖集和字型；缺少必需素材時顯示具體錯誤與重試按鈕。兩項是可重現的程式問題，實際 iPad 當時命中的問題仍待裝置驗證。
- 舊版字級預設較小。V2.2 把舊版 100% 字級遷移至新的「大字體」預設，保留舊版已加大的字級及其他設定。新版手動選的字級會在後續載入時保留。

## 驗收重製

- `npm run check`、`npm test`、`npm run build`。
- 有運行中的專案子路徑預覽時，`npm run test:presentation` 驗證 iPad 模擬的畫布、字型、全螢幕、NPC 觸控、配樂和缺少素材時的存檔保護。`npm run test:browser` 驗證桌面、手機和平板的遊玩回歸；設定 `SHADOW_TEST_OFFLINE=1` 同時驗證 PWA。
- `node test/update.mjs /path/to/v2.1 /path/to/v2.2-a /path/to/v2.2-b` 使用同一專案子路徑模擬三次發布；後兩個路徑應是分別建置的 V2.2。涵蓋舊快取、部署不同步、更新期間保留裝備 UID 與離線重開。
- `node test/capture-comparison.mjs before` 和 `node test/capture-comparison.mjs after` 分別指向兩版預覽。固定採 iPad Pro 11 橫向、相同角色出生位置、視窗尺寸及截圖裁切。
- `node scripts/verify-release.mjs https://kaya789142-alt.github.io/shadow-dungeon/ <commit>` 驗證正式版本。合併觸發的 Pages 流程會以發布的提交自動執行同一項檢查。

實機 iPad／iPhone Safari、長時操作的電量和熱負載仍待測。其他四職業使用正背面和分層程式動畫；逐職業的獨立八方向逐格資產仍有擴充空間。現有魔物的 51 個資料定義對應 16 個原創美術家族。
